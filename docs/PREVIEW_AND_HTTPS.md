# 1.8.0-preview：附件预览、视频自动播放与 HTTPS 传输

## 编辑器

- 选择图库媒体后，先复制到应用私有 filesDir 的 compose_media_* 文件，再上传；预览不再依赖上传成功或临时图库 URI。
- 图片可点击查看大图。视频尝试提取首帧 JPG 缩略图，点击可原生播放本地视频；缩略图提取失败时仍保留视频播放入口。
- 上传失败保留本地文件与草稿，支持重试、移除；未完成上传的附件禁止发布，避免提交空 URL/videoId。
- 附件及封面保存在当前账号、游戏草稿。移除附件或成功发布后清理对应本地副本；不删除原图库文件。
- 圆角标题、正文和附件卡片，统一按钮配色及沉浸材质，正文和附件整体可滚动，不再由巨大正文输入框挤压预览区。
- 本地副本会占用应用空间，大小上限仍为图片10 MB、视频50 MB；没有批量草稿缓存清理设置。

## 帖子视频

进入详情自动获取播放授权；视频在可视区域达到50%且页面活跃时自动播放，滑出或离开时暂停。视频区域20vp圆角并裁剪；正常播放不再显示刷新授权按钮，仅失败时显示重试。继承1.7.1可变长度HMAC密钥导入修复。

## 更新入口

新包只保留「一键更新.cmd」。它仍会选择并更新旧工程、保留签名/包名/SDK，并在备份旧版带版本号的更新脚本后删除这些旧入口。若更新失败，原脚本和其他替换文件一起回滚。

## 新增 HTTPS 传输环节

「我的 → 本地抓包诊断 → 测试 HTTPS 加密转发」。不需要打开游戏。

请求路径：UI进程系统HTTP客户端 → 指定 HTTP CONNECT 代理 198.18.0.2:49153 → 本应用 /32 VPN 路由 → lwIP → 已受系统protect保护的上游socket → 固定1.1.1.1:443 → Cloudflare。CONNECT 只允许 one.one.one.one:443，头部最多4096字节，不提供任意目标代理。TLS 密文原样双向转发。

前端通过系统 HTTPS 请求 https://one.one.one.one/cdn-cgi/trace（HEAD）。系统 CA、主机名校验保持默认开启，无自定义 CA，无跳过证书校验。收到完整最终HTTP响应（200–599，包括404）后，只向当前runId私有请求文件写入确认；扩展确认请求仍有效且Native确实读到TUN数据后才返回passed。没有用计时器设置成功。

回执 `testMode=https`、`phase=passed`、`cleanupConfirmed=true` 才表示本项成功；`tlsVerified=true` 只表示该固定测试连接通过系统TLS客户端验证。`gameCaptureImplemented=false`仍有效。该模式不是TLS中间人解密，不生成CA，不解密游戏包，不识别抽卡token。

## 验证范围及后续缺口

主机已编译 Native 并跑过 TCP 128 KiB 双向一致性、重传、清理回归；补充 CONNECT 逐字节分段、目标/端口限制、头部上限检查。服务模拟核对socket保护顺序、未收到前端HTTPS确认时不提交成功确认、当前runId文件回执。媒体本地副本、草稿URI持续有效、缩略图失败回退及资源释放的检查通过。

没有 Huawei SDK/真机；这不等于 ArkTSCheck/assembleHap、真实HTTPS通路、相册缩略图或自动播放已验收。建议先编译，依次验证附件预览、视频自动播放、HTTPS回执。

游戏阶段仍缺：实际鸿蒙游戏包标识、多连接和真实游戏目标路由、DNS/UDP/IPv6支持，以及独立本机TLS代理和用户证书信任流程。当前转发器仅能接受受限的测试流量；不能直接把默认路由交给它接管游戏，否则会破坏游戏联网。游戏是否信任用户安装的CA还需真机验证，不能仅凭VPN测试通过保证可提取抽卡授权。
